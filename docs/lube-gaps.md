# Lubrication reference — what is still missing

Generated from the fleet register and the imported masterlist.

**12 models, 26 machines** are production equipment with no lubrication
plan at all. A fitter sent to audit one of them now sees a screen saying the model
is unknown — which is better than the blank it used to be, and still nothing to
record.

Light vehicles, pickups, lighting towers and generators are deliberately not on
this list. 875 of those have no plan either, and a lube matrix for mining
equipment reasonably stops there. These twelve do not.

## What is needed for each compartment

**Capacity in litres**, **change interval in hours**, and the **OEM specification**
— the grade the manual calls for, not the brand on the drum. Which product meets
that specification is decided once, on the dashboard; the fitter is never offered
a choice of eight.

Nothing below is guessed. Where a figure is unknown the cell is blank, because a
plausible number in a lubrication table is worse than a visible gap — a blank gets
questioned and a number gets used.

## When the figures come back

They go into the masterlist spreadsheet, and mobile/lube.js is regenerated from it
by docs/build-lube-data.py. That file is generated and never hand-edited, so the
spreadsheet stays the one source and the next rebuild cannot quietly undo the work.

A single machine that differs from others of its model — a rebuilt transmission, a
retrofit — does not need a new model entry. That is what mobile/lube-overrides.js
is for.
